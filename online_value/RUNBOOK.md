## 0. 策略定义（已冻结，任何一条变动都视为"换策略"）

| 项 | 值 |
|---|---|
| 选股域 | 最近十年净利润 & 自由现金流双正的动态池（用 year-2 财务，避前视）；2026 年 303 只 |

| 持仓 | 分数最高的 **Top20，等权各 5%** |

| 不做的事 | **不含任何机器学习模型**；不剔金融股；不做择时；不设止损止盈 |

> 这组数字就是"合格线"。实盘长期严重偏离它，说明执行或数据出了问题，而不是"策略失效"——先查前者。

## 1. 每月做什么（时间线）

一个月只有**一个晚上 + 一个十分钟**的工作量。

### D-1 晚｜上月最后一个交易日 18:00 之后（数据源已更新日线与估值）

按顺序跑三条命令，**上一条 EXIT=0 才跑下一条**：

```bash
cd "/Users/11164591/Documents/Qoder目录/qlib/online_value"

# ① 更新数据（先看，后写）
/usr/bin/python3 monthly_update.py --dry-run > logs/mu_dry.log 2>&1; echo EXIT=$?
/usr/bin/python3 monthly_update.py         > logs/mu_run.log 2>&1; echo EXIT=$?

# ② 体检（16 项全 PASS 才算过）
/usr/bin/python3 preflight_check.py        > logs/preflight_run.log 2>&1; echo EXIT=$?

# ③ 出清单
/usr/bin/python3 gen_holdings.py           > logs/gen_run.log 2>&1; echo EXIT=$?
```

产出 `latest_buy_YYYYMMDD.csv`：Top20（各 5%）+ 5 只备选。

### D 日｜本月第一个交易日 14:45–14:55

按清单交易（规则见第 3 节）。全部完成后填 `trade_log.csv`。

### D 日之后到下月 D-1

**什么都不做。** 不看盘、不调仓、不补仓、不止损。

> **提前预演建议**：D-3（上月倒数第 3 个交易日）晚上先跑一次 `monthly_update.py --dry-run`。
> 它只读不写，能提前暴露"akshare 抓不到、bin 结构异常、池子规模异常"这类问题，
> 免得 D-1 晚上出错时手忙脚乱。

## 2. 检查什么（5 道关卡，每道都有明确通过标准）

### Gate 1 — 数据更新（看 `mu_run.log`）

| 检查项 | 通过标准 | 不通过怎么办 |
|---|---|---|
| Step0 预检 | 结构异常 0 只 | 脚本会自己 `exit 1` 且未写入任何数据。用 log 末尾的回滚命令还原，再排查 |
| 待补交易日 | 数量 = 上月剩余交易日数（约 18–23 天） | 若为 0：数据早已最新，正常；若远超 30：说明漏跑了月份，仍可继续 |
| 抓取成功率 | ≥ 90%（低于则脚本自动放弃写入） | 换时段重试；连续两晚失败 → 本月不交易，保持原持仓 |
| 追加结果 | `ok` 占绝大多数；`fail` ≤ 10 只 | `fail` 是复权基准无法校正被**主动跳过**（宁可不更新也不写错数）。若 fail 股出现在清单里，Gate 2 会拦下 |
| **复权 scale 分布** | **中位数 = 1.0000**；偏离 1 超 5% 的 < 100 只 | 中位数不等于 1.0000 → **立即停止**，说明基准比价算错了。偏离股是近期除权（7 月分红季约 40–50 只属正常）；超半数偏离 → 脚本会 WARN，人工核查后再定 |
| Step4 抽样 | 抽 6 只（含 scale 偏离最大的 3 只）：末值差 < 0.5% **且** 日收益偏差 < 0.3pp | 出现"异常!" → 立即回滚，不交易 |
| Step5 估值 | 行数/股票数/最新日期均不倒退 | 任一倒退脚本自动放弃写入，旧表不动，安全 |

### Gate 2 — preflight 体检（看 `logs/preflight_run.log`，必须 `EXIT=0`）

16 项分五组，**任何一项 FAIL = 本月禁止交易**：

- **A 口径常量锁**（6 项）：流动性阈值 50000、成本 0.004、Top20、回测末端 2026-07-31、月度换仓日规则（信号日严格早于执行日）、下一换仓点可定位
- **B 代码指纹锁**（1 项）：`core/` 9 个模块 + 3 个入口脚本的文件 md5 与 `golden/code_lock.json` 一致，报警时精确指出哪个文件
- **C 上游隔离**（2 项）：`core/` 与入口脚本**不出现任何 `import vXX`**；`frozen_src/` 快照仍在
- **D 数据鲜度**（5 项）：行情/估值截止日距今 ≤ 10 天、信号日可用、池子规模 150–500、估值截面覆盖 ≥ 95%、行情覆盖 ≥ 95%
- **E 黄金回归**（1 项）：重算 2026 年月度 Top20，**锁定文件里的每一期必须逐行完全一致**（容差 1e-4）；新增期数允许（8 月起会多出一期），锁定期数算不出来则 FAIL

> **E 项的语义是"历史不得被改写"**，不是"行数必须相等"——所以每月新增一期不会误报，而任何一期历史持仓变动都会被抓住。
>
> 这套锁已做过**故障注入验证**：故意改一个函数的 md5 和锁定持仓的第 6 行，
> 脚本准确报出"`compute_value_comp` 被改动"和"2026-01-05 rank6 不一致"并 `EXIT=1`。
> 它是可信的——**它报警就是真出事了，不要绕过。**

### Gate 3 — 清单人工三看（拿到 `latest_buy` 后，30 秒）

| 看什么 | 正常范围 | 超出怎么办 |
|---|---|---|
| 与上月持仓的重叠只数 | **≥ 16 只**（每月换 2–4 只） | 换 > 8 只：先别下单，检查池子规模是否突变（`gen_run.log` 里的池子只数）。确认无误再执行 |
| 池子规模 | 250–350 只 | < 150 只：数据缺失，暂停交易 |
| 金融股占位 | 3–8 只（历史月均 4.84） | > 12 只：不是错误，但记录在案。**不要手动剔除**（剔金融已实测否决：OOS −4.53pp） |
| 名单成分 | 无 ST、无退市风险、无 B 股、无上市 < 1 年 | 出现则手动跳过该只，用备选顺延，并在 log 记录（池子构造理论上已排除，出现即为数据问题） |

### Gate 4 — 成交后对账（当天收盘后，5 分钟）

- 实际成交只数 = 20（或"成交 N 只 + 明确记录 M 只未成交原因"）
- 每只市值占比 4.5%–5.5%
- 实际买入均价 vs 当日收盘价偏离 < 1%（超出说明下单时段或限价用错了）
- 填写 `trade_log.csv`

### Gate 5 — 月度绩效跟踪（每月 D-1 晚顺手记一行）

记录：账户月收益、沪深300 月收益、超额、账户历史最高点回撤。用于第 7 节的暂停判定。

## 3. 怎么买（执行规则）

1. **顺序**：先卖出（不在新清单里的旧持仓）→ 再买入（新进的）。避免资金不足。
2. **时段**：**14:45–14:55**。回测按次日执行价成交，尾盘最接近该口径。不要早盘买（波动大、偏离回测）。
3. **委托方式**：**限价单**。买入限价 = 当前价 × 1.005，卖出限价 = 当前价 × 0.995。不用市价单。
4. **仓位**：每只 5%。金额 = 总资金 / 20，向下取整到 100 股的整数倍。
   - 若某只单价过高导致 100 股 > 6% 资金 → 买 100 股就停，超配部分记录在案，不追加。
5. **涨停 / 停牌 / 一字板 买不进** → **按备选清单顺序顺延**（备选 1 → 备选 2 → …）。不追高、不次日追。
6. **限价未成交** → 次日同一时段（14:45–14:55）补一次。仍不成交则**放弃该只**，现金留到下月，**不摊到其他股**。
7. **首次建仓**：20 笔一次性买齐，约 20–30 分钟（券商有"篮子下单"功能可缩到 5 分钟）。之后每月只动 2–4 只，10 分钟内完成。
8. **账户**：建议用独立账户跑这个策略。不是技术必须，是为了对账干净 + 不和其他操作互相干扰纪律。

## 4. 硬性纪律（写下来就是为了不许破例）

- ❌ 月中不因任何消息、财报、暴跌、暴涨调整持仓
- ❌ 不设止损、不设止盈（回测的 25.56% 年化里已包含 −19.9% 的回撤，止损会切掉反弹）
- ❌ 不加杠杆、不做融券、不用衍生品
- ❌ 不"觉得这只不好"就手动替换清单成分
- ❌ 不因为某只涨了很多就提前卖（月频换仓自然会处理）
- ✅ 唯一允许的人工干预：清单里出现 ST / 停牌 / 明确退市风险时跳过并用备选顺延，且必须记录

| `universe.py` | **股票池**（十年双正 + year-2 财务避前视）· 代码格式化 · 名称表 | v5_xgb_turnover_comparative |

**为什么必须自包含**：上一级 `qlib/` 是实验目录，一直在优化迭代。以前生产与回测共用上游代码，好处是"实盘=回测"，代价是**上游改一行就会静默改变实盘持仓**。现在改成：`core/` 冻结，回测（`run_backtest.py`）与生产（`gen_holdings.py`）都只走 `core/`，两个目标同时达成。

**重构的正确性怎么证明的**（不是"看起来一样"，是逐位比对，见附录 A6）：
- 新代码重算 2019–2026 全部回测，**17 个字段与旧结果 diff = 0**（仅 turnover 差 2.4e-10，浮点求和顺序）
- 新代码重算 2026 七期 Top20，与重构**前**生成的 `golden/holdings_2026_locked.csv` **逐行完全一致**

数据依赖（3 处，与重构无关）：
- `~/.qlib/qlib_data/cn_data/` — 行情 bin + 交易日历
- `Qoder目录/valuation_cache.csv` — 估值（PE/PB/PS/PCF）
- `Qoder目录/fcf_cache_pit.csv` + `profit_cache_pit.csv` — 财务 PIT 表（决定股票池）

**上游快照** `frozen_src/`：7 个上游文件在上线时刻的副本 + `MANIFEST.md5`。**代码不引用它**，只作两个用途：① 需要追溯"重构前长什么样"时对照；② 上游被改坏时还原。preflight 的 C 项会检查它还在。

### 5.1 被锁住的东西

- **`core/` 全部 9 个模块 + 3 个入口脚本的文件级 md5**（锁在 `golden/code_lock.json`）
  改动任何一行 → preflight B 项 FAIL，并**精确报出是哪个文件**
- **5 个口径常量**：`LIQ_THRESHOLD=50000` · `FEE_ROUNDTRIP=0.004` · `TOPK=20` · `BT_END=2026-07-31` · 月度换仓日规则
- **2026 年 7 期 × Top20 的完整持仓**（`golden/holdings_2026_locked.csv`，141 行）
- **全期回测基线**（`golden/backtest_baseline.csv`）：已定格年份的收益必须逐位复现

> 从函数级锁改成文件级锁：自包含之后 `core/` 里每一行都是生产件，没有"无关代码"，所以文件级更严也更简单——连改注释都会报警，这是想要的效果。


### 5.2 想改策略时的唯一合法流程

```
① 在上游 qlib/ 里做实验（online_value/core/ 一行都别动）
② 实验版跑全期回测（2019–2026，跳过 2020）
③ 分别看 IS{2019,2021,2022} 和 OOS{2023,2024,2025,2026}
④ 判据：OOS 年化必须不下降。若"全期小赢但 OOS 输、优势集中在 IS 某一年"
   → 判定为曲线拟合，直接否决（剔金融就是这样被否掉的）
⑤ 通过了才把改动搬进 core/，然后 online_value 内跑 run_backtest.py，
   确认除有意改动外没有别的字段异动
⑥ 备份旧 golden/ → 更新 RUNBOOK 第 0 节锚点数字 →
   run_backtest.py --relock 与 preflight_check.py --relock 重建锁
⑦ 未通过：git 还原，core/ 与锁都不动
```

**每月换仓不涉及以上任何一步**——只跑 `monthly_update` → `preflight` → `gen_holdings`，代码零改动。

### 5.3 三条红线

1. **`--relock` 只在第 5.2 步 ⑥ 使用。** 绝不允许"体检 FAIL 了就 relock 让它变绿"——那等于把警报器拆了。
2. **`core/` 与 3 个入口脚本不允许"顺手改"。** 它们是生产件，连改注释都会触发指纹锁报警（这是设计意图）。
3. **每次 relock 前，把旧的 `golden/` 目录整个复制一份带日期的备份。** 锁的历史必须可追溯。

## 6. 异常处置速查

| 症状 | 原因 | 动作 |
|---|---|---|
| `monthly_update` Step0 报结构异常 | bin 曾被重复追加/写坏 | 已自动停止且未写入。用 log 里的回滚命令还原，排查后重跑 |
| 抓取覆盖 < 90% | 网络或数据源限流 | 脚本已放弃写入。换时段重试；两晚失败则本月不交易，**保持原持仓** |
| 某些股票 `fail`（复权 scale 异常） | 除权后基准变化超出安全区间 | 这是保护行为。若不在清单里可忽略；在清单里则 Gate 2 会拦，跳过该只用备选 |
| preflight B 项 FAIL | 有人改了关键函数 | **禁止交易**。用 git 查看改了什么。是误改 → 还原；是有意改 → 走 5.2 全流程 |
| preflight D 项 FAIL | 历史持仓被重算出不同结果 | **禁止交易**。多半是数据被改写（复权/回补），先查 `backup/` 对比 |
| preflight C 项 FAIL（鲜度） | 数据没更新成功 | 重跑 `monthly_update.py`；仍失败则本月不交易 |
| 清单与上月换了一大半 | 池子规模突变或数据缺失 | 先查池子只数。异常 → 不交易；确实正常（如年度池子换届）→ 照做 |
| 已回滚但还是不对 | 备份也被污染 | 停止交易，保持现状。等排查清楚再动 |

**一条总原则：所有异常的默认动作是"不交易，保持原持仓"。** 漏掉一次换仓的代价远小于按错误数据换仓。

## 7. 什么情况该暂停 / 复盘

**硬暂停（触发即停一个月，复盘后再决定）**
- 账户从历史最高点回撤 > **25%**（回测最大 −19.9%，25% 已属"超出历史经验"）
- 数据源（akshare / 估值接口）连续两个月不可用
- 池子规模连续两月 < 150 只，或估值覆盖率 < 95%

## 10. 终检回测（上线前 + 每年 1 月复盘 各做一次）

preflight 的黄金回归只锁**持仓名单**，不验证**收益**。所以还需要一道端到端确认：
「上线目录的代码 + 当前数据 → 还能不能跑出锚点收益」。

```bash
cd "/Users/11164591/Documents/Qoder目录/qlib/online_value"
/usr/bin/python3 run_backtest.py > logs/bt_recheck.log 2>&1; echo EXIT=$?
```

脚本自己会与 `golden/backtest_baseline.csv` 逐字段比对并在末尾打印结论，**`EXIT=0` 即通过**，不需要人工对表。判据：

| 字段 | 要求 | 违反说明什么 |
|---|---|---|
| 2019 / 2021 / 2022 / 2023 / 2024 / 2025 各年收益 | **必须复现到浮点末位**（容差 1e-12） | 这些年份数据早已定格。任何变化 = **历史数据被改写了**（复权回填、估值表被覆盖）→ 查清原因才能上线 |
| 2026 年收益 | 允许变 | 补了新交易日，当年收益自然变化 |
| 全期 `ar` / `sharpe` / `max_dd` | 允许小幅变（由 2026 传导） | 若 2026 没变而全期变了 → 异常 |
| `trades` 交易笔数 | 只允许增加（且增量 ≤ 20） | 减少 = 历史换仓记录变了，异常 |

> 容差为什么是 1e-12 而不是 0：不同求和顺序会带来浮点末位（~1e-17）噪声，而换掉一只持仓造成的年收益差异在 1e-3 量级——相差 9 个数量级，不存在被掩盖的可能。
> 另外读基线时必须用 `float_precision="round_trip"`：pandas 默认的快速解析器对 17 位有效数字会差 1 ULP，曾因此把两个**完全相同**的年份误判为 FAIL。**假警报比漏报更危险**，因为它会训练人习惯性忽略警报。

**上线时跑两次**：
1. 数据更新**前**跑一次 → 必须精确复现基线（`ar=0.2574751797`、`trades=262`）。
   复现不了 = 建锁之后代码或数据又变了，**上线推迟**，先排查。
2. 数据更新**后**再跑一次 → 按上表逐年比对，**只有 2026 变**才算数据更新干净。
