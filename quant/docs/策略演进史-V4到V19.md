> 答案：不是没试过复杂的，是复杂的全被实验否决了。每个版本的脚本都留在

## 全景图：三个时代

```
时代一：机器学习多因子（V4–V13）
  "让模型从 181 个因子里学出选股规律"
  → 能跑出 24.88% 年化，但暴露出模型退化、回撤大、换手高

时代二：消融与祛魅（V14–V15）
  "把策略拆开逐层检验：收益到底是谁贡献的？"
  → 惊人结论：ML 排序是负贡献(-10.69pp)，估值因子才是唯一正增量

时代三：做减法上线（V16–V19）
  "放弃 ML，规则化价值选股，把工程可靠性做到极致"
  → value_comp Top20：年化 25.7%、回撤 -19.9%、OOS 29.3%，2026-08-01 上线
```

一句话主线：**从"相信模型"走到"相信便宜"，从追求收益走到追求"回测=实盘"。**

## 第 0 章：预备知识——机器学习选股到底是怎么回事

> 不懂这一章，后面的"消融""早停""RankIC"都是天书。花五分钟读完，全文无障碍。

### 0.1 机器学习选股的流水线（所有 ML 版本共用这五步）

```
① 特征     每只股票每一天，算出一堆"描述它现状"的数字
            （过去60天涨了多少、换手率、市盈率、现金流增速……）
② 标签     告诉模型"正确答案"：这只股票未来20天涨了多少
③ 训练     模型在历史数据上学"什么样的特征组合 → 未来会涨"
④ 打分     拿训练好的模型给今天的股票逐只打分
⑤ 组合     按分数排序，买最高的10只/20只
```

关键：训练时"特征"必须全是过去的信息、"标签"必须全是未来的信息，两者绝不能穿帮——本项目一半的工程量都花在守这条线上（V13 的六项修复、6 层防作弊机制都是为它）。

### 0.2 决策树 → 梯度提升（GBDT）：XGBoost 和 LightGBM 的原理

- **决策树**：一连串 if-else 问题。"过去60天跌超10%吗？→是→换手率在放大吗？→是→打 0.7 分"。单棵树很笨，容易死记硬背。
- **梯度提升（GBDT）**：不用一棵大树，用**几百棵小树接力**——第 1 棵先粗糙地预测，第 2 棵专门学第 1 棵犯的错，第 3 棵学前两棵剩下的错……几百棵的意见累加起来就是最终分数。这是过去十年表格数据竞赛的统治级算法。
- **XGBoost 和 LightGBM**：同一套 GBDT 思想的两个著名实现（前者陈天奇 2014，后者微软 2016），像同一道菜的两位厨子——LightGBM 按"叶子优先"生长树、速度更快，XGBoost 正则化设计更细。**因为口味略有差异，两个都用再取平均（集成），比单用一个更稳。**

### 0.3 训练里的三个关键词

- **train / valid / test 三段切分**：train 用来学，valid 用来"模拟考"决定何时停止训练，test（真正的回测期）在训练全程**碰都不许碰**。
- **早停（early stopping）**：树的棵数不预先定死。每加一棵树就在 valid 上考一次试，成绩连续 100 轮不再提高就停，回退到历史最高分那一轮。停得太晚=死记硬背（过拟合），停得太早=没学会。**用什么指标当"考试成绩"，是 V14 暴出大问题的地方。**
- **RankIC**：衡量预测力的核心指标。某一天给全池股票打的分数排名，和它们未来20天实际涨幅排名的相关性。=1 完美预测，=0 纯随机。选股场景日均 RankIC 能到 0.05 就是有用信号，0.1 已经很强。

### 0.4 滚动训练：为什么每年要重训一遍

市场规律会变（风格轮动、制度变化），2016 年学出的规律到 2024 年可能失效。所以不训"一个用八年的模型"，而是**每年滚动重训**：

```
预测2023年用的模型 ← 用2018-2021训练 + 2022当valid（12月留白）
预测2024年用的模型 ← 用2019-2022训练 + 2023当valid（12月留白）
……每年窗口向前滑一格，永远只用"当时已知"的数据
```

"12 月留白"叫 **embargo**：因为标签是未来 20 天收益，valid 段 11 月底就截止，防止 valid 的标签窗口伸进 test 期偷看答案。

## 时代一：机器学习多因子（V4–V13）

### V4 —— 特征剪枝与价值因子融合实验
`v4_optimization.py`

- **背景**：基线是"5 年滚动训练 + Top10 + Alpha158Enhanced 量价因子 + 5 个 FCF 基本面因子"。
- **做法**：三个实验——E（砍掉重要性后 50% 的特征给价值因子腾位置）、F（PE 分位数 >90% 直接剔除）、G（模型分数与价值分数加权融合）。
- **意义**：第一次意识到"价值因子"可能比模型本身重要，为后面的路埋下伏笔。

### V5 —— 多因子 ML 的成熟形态（研究框架的主结果）
`v5_new_baseline.py` 等 20+ 个 v5_* 脚本；现代码整理进 `quant/core/` + `run_rolling.py`

这是"机器学习路线"的完整体，值得拆开看清每个零件：

- **特征（模型的眼睛，约 181 个）**，分三类：
  1. **Alpha158**（158 个）：qlib 内置的经典量价因子库，全部由"开高低收量"加工而来——K线形态（今天实体多长、上影线多长）、各周期动量（5/10/20/60 日涨幅）、波动率、量价相关性、均线偏离等。相当于把技术分析里能量化的东西全算一遍。
  2. **长周期扩展**（14 个，`Alpha158Enhanced` 类）：Alpha158 最长只看 60 天，这里补上 120/240 日的动量（ROC120/240）、均线（MA120/240）、波动（STD120/240）、布林位置（BOLL60/120）、量比（VMA、VRATIO）、量价相关（CORR_PV）——月频换仓需要更长的记忆。
  3. **FCF 基本面**（5 个）：FCF 增速、净利增速、FCF/净利比（利润含金量）、3年平均FCF、3年FCF变异系数（稳定性）。**严格 PIT**：Y 年年报的因子从 Y+1 年 5 月 1 日才开始"被模型看见"。
- **标签（模型要预测的答案）**：`Ref($close,-20)/$close - 1`，即**未来 20 个交易日的收益率**（约一个月，和月频换仓对齐），再做按日截面标准化——模型学的不是"会涨多少"，而是"同一天里谁比谁涨得多"。
- **模型（双厨子 + 合议）**：
  - XGBoost：学习率 0.005 的慢火（最多 1000 棵树），树深仅 4 层，L1/L2 正则 10/50——**参数全往"保守"里调**，因为股价信号极弱，激进的模型只会记住噪声；
  - LightGBM：学习率 0.02、树深 8 但重正则（L1=50, L2=200），风格稍激进，与 XGB 形成互补；
  - **ENS 集成**：每天把两个模型各自的打分转成池内排名百分位（0~1），再取平均。用排名而不是原始分数，是因为两个模型分数量纲不同，排名才公平——**和 value_comp 合成四个估值因子是同一招**。
- **滚动训练**：每年重训（4 年 train + 1 年 valid + embargo 12 月留白，见第 0 章），信号段月末取 Top10 等权，T+1 成交。
- **结果**：ENS Top10 **年化 24.88%（剔 2020）**，Sharpe 1.04，**最大回撤 -33.95%**。
- **V5 时期打的补丁**（每个都是一次教训）：
  - `v5_nolookahead.py`：无前视校验
  - `v5_backtest_audit.py`：回测审计（后来发现的问题在 V13 集中修复）
  - `v5_decay_analysis.py`：信号衰减分析
  - `v5_production_*.py`：第一次尝试生产化
- **决策**：24.88% 成为研究框架的锚点数字，但 -34% 的回撤已经让人不安。

### V6–V9 —— 加法尝试与频率消融
`v6_advanced_optimizations.py` / `v6_breakthrough.py` / `v6b/v6c` / `v9_rolling_frequency_test.py`

- **V6 系列**：各种"突破性优化"组合拳（特征、参数、组合规则），没有产生质变。
- **V9**：重训频率消融——月/季/半年/年四档对比，确立九大指标输出格式（年化/波动/夏普/回撤/Calmar/IC/RankIC/换手/交易数），这套格式沿用至今。
- **决策**：加法路线收益递减，转向"先把回测的正确性做扎实"。

### V13 —— 大修：把回测里的水分全部挤掉
`v13_fixed_compare.py`

- **背景**：审计（`v5_backtest_audit.py`）发现回测有系统性虚高。
- **六项修复**：
  1. 流动性过滤改用 `close×volume` 口径（qlib 的 `$amount` 字段是空的！），失败必须报错不许静默跳过
  2. 交易成本：往返 0.4%（买 0.15% + 卖 0.25% 含印花税）
  3. **T+1 执行**：T 日收盘出信号，T+1 收盘价建仓，消除同日成交前视
  4. 特征选择去前视：只许用窗口内训练集选 Top80 特征
  5. valid embargo：验证集提前结束，防 20 日标签泄漏进测试期
  6. 速度优化（hist 树 + 多线程）
- **决策**：**"数字变难看但真实" > "数字好看但作弊"**。V13 之后的所有版本都继承这套修复。这是全项目的方法论转折点。

## 时代二：消融与祛魅（V14–V15）

### V14 —— 消融实验：收益到底是谁贡献的？
`v14_ablation.py`（另有 `v14_survivorship_check.py` 查存活偏差、`v14_diag.py` 诊断模型）

- **做法**：逐层叠加，看每层的边际贡献：
  - **E0**：股票池等权拿着（无模型）—— 基准，年化 **12.24%**
  - **E1**：E0 + XGB 排序 Top20
  - **E2**：E1 + 估值因子（EP/BP/SP/CFP/PEG）
  - **E3**：E2 + 深度基本面（ROE/毛利率/营收增速等）
- **惊人结论**：
  - **E1 - E0 = -10.69pp：XGB 排序是负贡献**——模型选的还不如整个池子等权拿着
  - **E2 - E1 = +2.78~+5.41pp：估值因子是唯一稳定的正增量**
- **V14 诊断还发现**（`v14_diag.py`）：27 个训练窗口中 6 个 `best_iter=0`——模型在第 0 轮就"停止学习"，输出接近常数，Top20 退化成伪随机选股。

  **根因值得展开讲，这是全项目最有教育意义的 bug**：当时早停用的考试指标是 **RMSE**（预测值与答案的均方误差，"猜得准不准"）。但标签做过标准化，均值为 0——对这种极弱信号，模型每学一点排序规律，预测值就会偏离 0 一点，**RMSE 反而变大**。于是在"RMSE 越小越好"的考官眼里，什么都不学、全部输出 0 的第 0 轮就是"最优"，早停当场收工。
  一句话：**考试考错了科目**——我们要的是"排序能力"（谁比谁强），考官却在考"绝对数值猜得准不准"，而这两件事在弱信号下互相矛盾。
- **决策**：模型不能再用 RMSE 早停；更重要的疑问被摆上桌面——**要模型干什么？**

### V15 —— 给模型最后一次机会
`v15_model_fixed.py`

- **核心修复：早停指标 RMSE → RankIC 最大化**。自写了一个高速评估器（现 `core/models.py` 的 `RankICEval`）：每加一棵树，就算一次"valid 段每天的预测排名 vs 实际涨幅排名的相关性、再对天数取平均"，用它决定何时停——**考官终于开始考正确的科目**。
- **配套保险**（都进了现行代码）：
  - **fallback 机制**：若早停在 30 轮以内就停了（说明超参和该窗口数据不合），自动换 2 套备选超参（更慢的学习率/更浅的树）重训，按 valid RankIC 择优——只用 valid 集裁决，不碰 test，无穿越；
  - **收敛检查**：`best_iter=0` 直接抛异常拒绝往下跑（`check_convergence`），不许带病回测；
  - **退化保护**：某窗口 valid RankIC < 0.005 时，该年放弃模型、回退为全池等权——"没把握时不下注"；
  - 沪深300 基准换用干净的外部缓存（qlib 内置的 SH000300 在 2019 后是坏的）。
- **结果**：修复后 27 个窗口再无 `best_iter=0`，模型确实在学东西了——但排序增量仍然干不过简单的估值因子。
- **决策**：**放弃"ML 做主力"路线**。机器学习在这个 300 只优质池、月频、弱信号的场景里，学不出超越"买便宜的"的规律。

## 时代三：做减法上线（V16–V19）

### V16 —— 规则化价值选股：value_comp 诞生
`v16_value_rules.py`（另有 `v16_fin_compare.py` 初查金融股问题）

- **思路**："人肉价值选择"的系统化——不用 ML，用有文献先验的因子直接排序，杜绝数据挖掘。
- **做法（抗过拟合设计）**：
  - Part A：候选因子（ep/bp/cfp/sp/roe/value_comp/动量/反转/低波）在池内做五分位分层检验，**IS=2019-2022 选因子，OOS=2023-2026 验证**
  - Part B：胜出者用与 E0 完全一致的引擎回测（T+1/0.4%/流动性/涨停停牌过滤）
- **结果**：`value_comp`（四估值倒数 rank 均值）胜出——比任何单一估值因子都稳，比动量/低波类都强。
- **决策**：**value_comp 成为策略核心**。附带发现：季频口径下"剔金融"结论矛盾（全期赢 2.1pp 但 OOS 输 3.5pp，优势全在 2019 样本内）——挂起待月度口径重判（→V19）。

### V17 —— 残差模型：给 ML 留的一扇小窗
`v17_residual_model.py` / `v17_pit_universe.py`

- **思路**：既然估值是基本盘，那让 ML 只学"便宜之外"的东西。

  **"残差"是什么**：把每期"未来 60 天超额收益"对 value_comp 做截面回归——相当于先问"这段收益里有多少能用'它便宜'来解释？"——**解释不掉的剩余部分就是残差**。拿残差当标签训练，模型学到的就必然是估值之外的规律（催化剂），和 value_comp 天然不重复（正交）。
- **模型具体长什么样**（和 V5 的主力模型是刻意反着来的）：
  - **特征只有 12 个**，而不是 181 个：动量（60/120日）、短期反转（5/20日）、换手异动、特异波动、beta、盈利加速度、营收加速度、ROE 环比、月份——**严格剔除一切估值因子**，防止和 value_comp 共线（否则模型会偷学"便宜"，正交就假了）；
  - **XGBoost 换用 `rank:pairwise` 目标**：不再回归数值，直接学"两两配对谁排前面"，任务和目标终于完全一致；
  - **树浅到只有 3 层、每片叶子至少 8 个样本、每棵树只随机看 40% 的特征**——参数保守到近乎苛刻，因为残差信号比原始收益信号还弱；
  - RankIC 验证集早停（V15 的教训已内化成标配）。
  - **融合**：`Final = a·rank(value_comp) + (1-a)·rank(残差预测)`，a 试了 0.5/0.7/0.85——估值永远占大头，模型只是加味。
- **配套**：`v17_pit_universe.py` 把股票池缓存升级为 PIT 增广版（含退市股），修存活偏差。
- **决策**：架构上正交化是干净的，但残差信号本身弱，为 V18 的全面检验做铺垫。

### V18 —— 全栈增强 + 终极对比：模型的告别演出
`v18_full_stack.py` / `v18_launch_metrics.py` / `v18_verify.py`

- **做法**：在 V17 上一次性叠加四层：
  - L0 存活偏差修正（PIT 增广池含退市股）
  - L1 **季频→月频**（训练配对样本翻 3 倍，缓解模型退化，换仓更及时）
  - L2 催化剂特征 12 → 18 个，新增 6 个与估值低相关的正交因子：`max_ret_20`（彩票效应：近20日单日最大涨幅，暴涨过的往往后继乏力）、`amihud_20`（非流动性溢价）、`skew_20`（收益偏度）、`high_prox`（距 52 周高点距离）、`gm_accel`（毛利率加速度）、`debt_chg`（负债率变化）
  - L3 动态 α 融合（当期 valid RankIC 高 → 多信模型，低 → 多信估值）+ Top15 集中版对比
- **终极对比结果**（quant 研究引擎同口径，剔2020）：**模型年化略高，但纯估值在风险调整后全面占优**：
  | 策略 | 年化(剔2020) | Sharpe | 最大回撤 | Calmar |
  |---|---|---|---|---|
  | 集成 ENS Top10（含ML） | 24.88% | 1.04 | **-33.95%** | 0.81 |
  | **value_comp Top20（无ML）** | 23.00% | 1.00 | **-19.34%** | **1.06** |

  多赚不到 2 个点的年化，代价是回撤深了 14.6 个点——**你在 -34% 的坑底大概率拿不住**。而按上线口径（2019–2026 跳过 2020）重测，value_comp Top20 达到 **25.75% 年化 / Sharpe 1.26 / 回撤 -19.9%**（`golden/backtest_baseline.csv`），成为最终锚点。
- **决策（全项目最重要的一个）**：**上线版彻底去掉模型链路**。`use_model=False` 时 `score = value_comp rank` 恒成立——模型对持仓零影响，那就不该让它留在生产代码里。上线策略定名 **value_comp_M20**（月频纯估值 Top20 等权）。

### V19 —— 上线前最后一问：剔不剔金融股？
`v19_fin_monthly.py`

- **背景**：V16 的季度口径下这个问题结论矛盾，上线口径已改月度+PIT 池，必须重判。
- **做法**：两版回测唯一差异 = 是否剔除 8 只银行保险股，其余口径与上线版完全一致。
- **结果**：**剔除金融股 OOS -4.53pp**——优势全部集中在 2019（样本内某一年），典型的曲线拟合特征。
- **决策**：**不剔金融**。并由此确立否决准则：*"全期小赢但 OOS 输、优势集中在 IS 某一年 → 判定为曲线拟合，直接否决。"* 这条准则写进了 RUNBOOK 5.2 的改策略流程。

## 上线工程（2026-07-29）：把"不许漂移"做成机器可验证

策略定了，最后的工程问题是：**怎么保证实盘跑的永远是回测验证过的那套代码和数据？**

### 自包含重构
上线目录原本只是薄壳，真正的计算逻辑散在 8 个上游 `vXX` 实验脚本里——而那些脚本还在天天改，**上游改一行就会静默改变实盘持仓**。7-29 重构：函数体逐字搬进 `online_value/core/`（不做任何"顺手优化"，连取数区间的边界天数都原样保留），切断全部上游依赖。

**重构正确性的三重验证**（不是"看起来一样"，是逐位比对）：
1. 从零重算 2019–2026 回测：17 个字段与旧结果 **diff = 0**（仅 turnover 差 2.4e-10，浮点求和顺序）
2. 重算 2026 年 7 期 Top20：与重构前锁定的黄金持仓 **141 行逐行一致**
3. 新旧代码各出一份买入清单：**逐字节相同**

### 防漂移三层锁 + 每月 18 项体检
- **代码指纹锁**：14 个生产文件 md5 锁定（连判据文件自己也在锁里——否则锁可以被悄悄重建，绿灯失效比红灯更坏）
- **黄金持仓锁**：历史持仓逐行锁定，语义是"历史不得被改写"
- **历史数据指纹**：88 万行估值 + 抽样行情指纹，防上游数据回填改写历史
- 全部做过**故障注入验证**：改一行注释、改一个 pe_ttm 的万分之一，都能被精确抓出。**它报警就是真出事了，不要绕过。**

### 想改策略？唯一合法流程（RUNBOOK 5.2）
```
上游实验 → 全期回测 → 分看 IS/OOS → OOS 不下降才通过
（"全期赢但 OOS 输"= 曲线拟合，直接否决）
→ 搬进 core/ → 终检回测 → 备份旧锁 → relock
```

## 番外：把 qlib 的全部内置模型拉出来遛一遍（`run_benchmark.py`，研究仍在继续）

策略上线后有个自然的疑问：**"是不是只是 XGB/LGB 不行？换深度学习呢？"** 于是把 qlib 内置的全部 14 个模型放进同一套无穿越管线做头对头（同特征、同股票池、同回测规则，谁也不许开小灶）。先认识一下选手：

| 类别 | 模型 | 一句话原理 |
|---|---|---|
| 线性 | **Linear** | 最朴素的基准：每个特征乘一个固定权重再加总。学不了"组合条件"，但最不会过拟合 |
| 梯度提升树 | **XGBoost / LightGBM** | 见第 0 章：几百棵小树接力纠错 |
| 梯度提升树 | **CatBoost** | GBDT 第三名厨（Yandex 出品），排序式提升设计，减少梯度估计偏差 |
| 树集成升级 | **DoubleEnsemble** | 微软的"LightGBM 套娃"：训练多个 LGB，每轮给"难学的样本"加权、给"没用的特征"降权，双重集成 |
| 神经网络 | **MLP** | 多层感知机：特征加权求和→非线性变换，堆几层。最基础的神经网络 |
| 神经网络 | **TabNet** | Google 的表格专用深度网络，带"注意力选特征"机制 |
| 循环网络 | **GRU / LSTM / ALSTM** | 把每只股票**过去 20 天的特征序列**按时间顺序喂进去，带"记忆门"决定记住/遗忘什么。ALSTM 加注意力，自动挑序列里重要的日子 |
| 卷积 | **TCN** | 时间卷积网络：用一层层"扩张卷积"扫时间序列，感受野指数扩大 |
| 注意力 | **Transformer / Localformer** | GPT 同款架构：序列里任意两天直接两两"对话"算相关性。Localformer 加了局部卷积偏置 |
| 图注意力 | **GATs** | 图注意力网络：不但看单只股票的序列，还让**股票之间互相传递信息**（"和我相似的股票最近怎么走"） |

> 与滚动引擎的差异：这条基准管线用 qlib 原生 DatasetH/TSDatasetH（序列模型看过去 20 天窗口）；本机无 GPU，全部深度模型强制 CPU，每个模型限时 45 分钟，超时记 `timeout`、报错记 `failed`——绝不静默跳过。

**Phase A 初筛结果**（单一固定切分，test=2023~2026H1，按 OOS RankIC 排名）：

- **GATs 排名第一**（RankIC 0.1841、年化 41.9%、Sharpe 2.40）——但**高度存疑**：比第二名高出近一倍，很可能是单切分恰好命中它擅长的行情，或注意力机制在 300 只的小池子上过拟合。**结论要等 Phase B 多窗口滚动验证，未验证前不作数**（V19 的教训：单窗口的辉煌多半是曲线拟合）；
- **第二名就是 VALUE20**——纯估值规则，用时 14 秒，把 12 个需要几分钟到几十分钟训练的模型甩在身后；
- Transformer、LSTM、GRU 等深度模型全部平庸（RankIC 0.05~0.08，和树模型一个水平），TabNet、TCN 直接超时出局。

**目前的阶段性答案**：不是 XGB/LGB 不行，是**这个场景对所有模型都很难**——300 只精选池里的月频弱信号，换什么架构都学不出稳定超越"买便宜的"的规律。GATs 是唯一悬念，留待 Phase B 裁决。

## 沉淀下来的方法论（比策略本身更值钱）

1. **先挤水分，再谈收益。** V13 之前的所有好数字都不可信。回测的第一要务是"不作弊"：PIT、embargo、T+1、真实成本、流动性，一个都不能少。
2. **消融实验是照妖镜。** 不拆开逐层测（V14），永远不知道 24.88% 里模型其实是 -10.69pp 的负贡献。收益要能说清楚"是谁贡献的"。
3. **OOS 是唯一的裁判。** 剔金融股全期赢、OOS 输 → 否决。任何"优势集中在样本内某一年"的改进都是曲线拟合。
4. **弱信号场景，简单规则打败复杂模型。** 300 只优质池 + 月频 + A股噪声，ML 学不出稳定超越"买便宜的"的规律；模型还带来退化风险（best_iter=0）和 -34% 的回撤。
5. **风险调整后收益 > 绝对收益。** 24.88%/回撤34% 输给了 25.75%/回撤20%。你能拿住的策略才是好策略。
6. **上线的敌人不是市场，是自己。** 防漂移三层锁防的全是"自己人"：顺手改代码、误跑 relock、上游重抓数据。所有异常的默认动作是"不交易，保持原持仓"。
7. **每个版本都留档。** `archive/legacy_scripts/` 里 60+ 个脚本是这条路的完整脚印——否决一个方向的实验和采纳一个方向的实验同样值钱，它们防止你两年后把老路再走一遍。
